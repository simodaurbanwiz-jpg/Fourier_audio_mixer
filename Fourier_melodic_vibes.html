    HOW SYNC WORKS: The BPM analyzer scans the audio waveform using an autocorrelation energy algorithm on the low-frequency content (kick/bass band). Once BPM is detected, SYNC adjusts the target deck's playbackRate so that BPM_target × rate = BPM_master. Master Sync Lock keeps both decks locked — any tempo change on the master propagates to the slave automatically. Phase alignment nudges the slave deck's position so beat 1 lines up with the master.

    ⚡ FOURIER THEORY POWERING THIS APP
    1. FOURIER SERIES
    f(t) = a₀/2 + Σₙ₌₁^∞ [ aₙ·cos(nω₀t) + bₙ·sin(nω₀t) ]
    Any periodic signal can be expressed as an infinite sum of sine and cosine waves. ω₀ = 2π/T (fundamental angular frequency) aₙ = (2/T) ∫ f(t)·cos(nω₀t) dt (cosine coefficients) bₙ = (2/T) ∫ f(t)·sin(nω₀t) dt (sine coefficients) MUSICAL MEANING: A guitar string at 440 Hz also vibrates at 880, 1320, 1760 Hz (harmonics). Timbre — why a piano sounds different from a violin at the same pitch — is determined by which harmonics are present and how strong they are (the aₙ and bₙ coefficients). The DEMO SYNTH tone this app generates IS a Fourier Series: audio(t) = 0.8·sin(2π·60t) + 0.5·sin(2π·110t) + 0.4·sin(2π·220t) + 0.6·sin(2π·440t) + …
    2. DISCRETE FOURIER TRANSFORM (DFT) & FFT
    X[k] = Σₙ₌₀^{N-1} x[n] · e^(-j2πkn/N) k = 0, 1, …, N-1
    The FFT (Cooley-Tukey algorithm) computes the DFT in O(N log N) instead of O(N²). This app uses the browser's built-in AnalyserNode which runs FFT on the live audio stream. Frequency of bin k: f_k = k · (sample_rate / N) Example (SR=44100, N=2048): bin 20 ≈ 430 Hz (near Concert A = 440 Hz)
    3. FILTER PIPELINE — How EQ, Bass, Treble, and Filters work
    x[n] → FFT → X[k] × H[k] → IFFT → y[n]
    H[k] is the filter mask — it controls what gets through at each frequency: Low-pass: H[k] = 1 if f_k < cutoff, else 0 → keeps bass, removes treble High-pass: H[k] = 1 if f_k > cutoff, else 0 → keeps treble, removes bass Notch: H[k] = 0 for lo < f_k < hi → eliminates one frequency band Bass boost: H[k] *= 2.5 for 20 < f_k < 250 Hz → amplifies bass bins Beat isolate:H[k] = 1 only for 50 < f_k < 300 Hz → kick drum region only CONVOLUTION THEOREM: Multiplying in the frequency domain = convolving in the time domain. This is why FFT-based filtering is so efficient. In the browser, this app uses BiquadFilterNodes and GainNodes which are hardware-accelerated implementations of exactly this pipeline inside the Web Audio API.
    4. HANNING WINDOW
    w[n] = 0.5 · (1 – cos(2πn / (N–1)))
    The FFT assumes the analysis window repeats cyclically. If the signal doesn't match at the edges, "spectral leakage" occurs — fake frequency components appear in the spectrum. The Hanning window tapers the signal to zero at both edges, eliminating leakage. The AnalyserNode applies this automatically in the SPECTRUM tab.
    5. NYQUIST-SHANNON THEOREM
    f_sample ≥ 2 · f_max
    To faithfully represent a signal digitally, the sample rate must be at least twice the highest frequency. Browser audio uses 44,100 Hz or 48,000 Hz sample rate, allowing frequencies up to 22,050 / 24,000 Hz — covering all of human hearing (20–20,000 Hz).
    6. THIS APP'S AUDIO PIPELINE
    AudioBufferSourceNode (file / synth) └─ GainNode (volume per deck) └─ BiquadFilter (high-pass) └─ BiquadFilter (low-pass) └─ BiquadFilter (bass shelf — EQ) └─ BiquadFilter (mid peaking — EQ) └─ BiquadFilter (treble shelf — EQ) └─ AnalyserNode (FFT for spectrum display) └─ GainNode (crossfade mix) └─ GainNode (master volume) └─ AudioContext.destination (speakers)
